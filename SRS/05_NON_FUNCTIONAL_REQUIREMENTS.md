# 05. Non-Functional Requirements

**Version 2.1.0 — As-Built Edition**

Non-functional requirements are assessed against the same rule set as the functional ones. Measurable runtime targets that cannot be confirmed without executing the system are marked **Not Verifiable Statically**, and the audit instead records the concrete code-level enablers or blockers found.

**Coverage: 2 Implemented · 11 Partial · 3 Missing · 4 Not Verifiable Statically — of 20 requirements.**

## 5.2 Security & Data Privacy

| Req ID | Requirement | Status | Evidence / Findings |
| :--- | :--- | :--- | :--- |
| NFR-SEC-01 | bcrypt hashing, ≥ 10 salt rounds, no plaintext | **Implemented** | `bcrypt.hash(x, 10)` consistently at `adminController.js:411,505,553,590,694,747`; `passwordController.js:113-116`; `scripts/createAdmin.js:20`; `scripts/createProfessionalSupervisor.js:22`. Meets but does not exceed the minimum. **Caveat:** plaintext fixture passwords are committed in `test/test.server.js:12,25,90` |
| NFR-SEC-02 | Signed JWT via `JWT_SECRET` with explicit expiry | **Partial** | `JWT_SECRET` is read from the environment and expiry is set (`generateJWT.js:11-14`, `expiresIn: "1d"`) and verified in `authMiddleware.js:16-19`. **Gaps:** expiry is hardcoded rather than environment-driven; no algorithm pinning, issuer or audience; no secret-strength validation, so an empty secret silently disables authentication; no HTTPS/HSTS enforcement and `cors()` is fully open (`server.js:227`) |
| NFR-SEC-03 | `protect` + role `authorize` on every endpoint | **Implemented** *(was Partial — fixed 2026-09-14)* | Every route now carries both `protect` and a role guard. The previously unguarded `POST /api/ai/review`, `POST /api/ai/review-report`, `POST /api/ai/writing-assistant` and `GET /api/ai/writing-assistant/quota` are now restricted to `student`, `academic_supervisor` and `professional_supervisor` — the roles that actually have an AI surface in the client. This closed a hole where **any** authenticated account (including `admin`) could spend AI requests that, because the quota is attached to a `Student` row, were never charged to them. Verified: admin → 403, student → passes the guard, anonymous → 401. Public by design: login, forgot-password, verify-otp and reset-password (the caller is locked out by definition); one legacy timeline read is `protect`-only but role-agnostic intentionally |
| NFR-SEC-04 | Exact MIME allow-list, 10 MB cap, header stripping | **Partial** *(improved 2026-09-14)* | **Fixed:** the AI uploader — previously **20 MB**, which both exceeded the cap and buffered 20 MB of RAM per request — is now 10 MB with an exact `application/pdf` MIME check (`middleware/uploadMiddleware.js`). The student report uploader now requires the declared MIME type **as well as** the `.pdf` extension; it previously accepted any file merely *named* `*.pdf`. Multer's limit errors are translated into clean JSON, so an over-sized upload returns **413** with a readable message instead of an opaque 500. Verified: 11 MB → 413, non-PDF → 400, `text/plain` named `.pdf` → 400, valid PDF → accepted. **Still open:** the CSV path accepts `text/csv` **or** any `.csv` filename, and **no script-header or executable-content stripping exists anywhere** |
| NFR-SEC-05 | Corpus restricted to academic supervisors/admins; snippet-only exposure | **Missing (Roadmap)** | Depends on the non-existent repository and scan storage. Stored report content is additionally exposed to students and professional supervisors on the workspace endpoint (`reportWorkspaceRoutes.js:7-9`), and nothing implements snippet-only match display |

## 5.3 Reliability & Data Integrity

| Req ID | Requirement | Status | Evidence / Findings |
| :--- | :--- | :--- | :--- |
| NFR-REL-01 | Explicit FK referential integrity (`CASCADE` / `SET NULL`) | **Partial** *(was Missing — corrected 2026-09-14)* | **Correction to the original audit:** Sequelize infers `references` from associations, so `sync()` **does** create foreign keys even though no model declares `onDelete`. A freshly synced schema carries **13 FK constraints**: `defensealerts→students CASCADE`, `internships→students CASCADE`, `internships→users SET NULL` (both supervisor columns), `meetings→students SET NULL`, `meetings→users CASCADE`, `notifications→users CASCADE`, `reportcomments→reports CASCADE`, `reportcomments→users CASCADE`, `reports→students SET NULL`, `students→users CASCADE`, `tasks→students CASCADE`, `tasks→users CASCADE`. **But the live `internsmart` database has only 7**, because `sync({ force: false })` never adds constraints to tables that already exist — it is missing `internships→students`, `internships→users` ×2, `meetings→students` and `tasks→users`. Policies are also inferred rather than explicitly declared. Integrity therefore holds on a fresh schema but is only partially enforced in the running database |
| NFR-REL-02 | 100 % cascade cleanup across all tables on user deletion | **Partial** | The routine (`adminController.js:299-363`) covers report comments (by report and by user), reports, internships, meetings, tasks, defence alerts, the student row, notifications, and prunes/destroys group meetings. **Gaps:** the three plagiarism tables cannot be cleaned because they do not exist; timeline settings are never considered; and there is **no transaction**, so a mid-sequence failure leaves already-committed deletions and thus orphans. Dangling integer references persist for `Task.feedbackAcademicBy`/`feedbackProfessionalBy` and `Internship.academicGradeSubmittedBy`/`professionalGradeSubmittedBy`. Manual scripts (`scripts/checkOrphans.js`, `cleanOrphans.js`) exist but are never invoked automatically and also miss those columns |
| NFR-REL-03 | Fail-safe external-service isolation with rollback | **Partial** *(was Missing — substantially improved 2026-09-14)* | Three compensations are now in place and verified. **Deletion:** `deleteUser` runs in one transaction. **CSV import:** each row runs in its own (a failure forced after `User.create` rolled back to zero). **AI review:** PDF text is now extracted *before* any state change, the report's prior status/progress is captured, and any failure restores it and refunds the daily request — verified with a deliberately invalid API key (report returned to `submitted`/0, quota charged to 2 then refunded to 1). The same compensation was added to both `/api/ai/review` and the writing assistant. **Still open:** SMTP failures are downgraded to warnings *after* the user row is committed, and emails for an imported row are sent inside that row's transaction, so a mid-row rollback could accompany an already-sent credential email |

## 5.6 Interpretation of the Performance Results

`NFR-PERF-01`–`NFR-PERF-04` are load- and latency-bound targets that require a running deployment to confirm; they are not evidence of failure. What the audit establishes is that **three of the four have concrete architectural blockers in the current code** (no indexing/caching strategy, no background job for AI, no code-splitting), while `NFR-PERF-03` is untestable because the plagiarism capability does not exist. Validating these four targets should follow, not precede, the remediation items in §06.
